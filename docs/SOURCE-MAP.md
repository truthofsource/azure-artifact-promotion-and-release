# Design source and evidence boundaries

This project is based on the operational platform's release stages, not a newly commissioned cloud pipeline.

| Platform reference | Pattern taught here |
| --- | --- |
| `careops-promotion-candidate.yml` | Verify the exact successful nonproduction run, source and acceptance evidence before selecting a release. |
| `careops-archive-release.yml` | Retain actual package bytes and associated metadata independently of a source branch. |
| `careops-production-release.yml` | Verify archives and target readiness; publish without rebuilding; check runtime behavior and record active bindings. |
| `careops-production-rollback.yml` | Separate read-only candidate preparation from account-bound execution and revalidation. |
| `careops-nonproduction-rollback-rehearsal.yml` | Rehearse recovery in isolation and restore original settings and paused state. |

Names identify source concepts; operational YAML and account-specific publisher code are not copied wholesale into this public project. The templates are newly written teaching adaptations with an explicit adapter contract and no live target configuration.

The Python implementation and its tests were created for this project. All package contents, source identifiers and settings are fictional; the local validation receipt was generated by running these tests, not borrowed from a cloud acceptance receipt.
